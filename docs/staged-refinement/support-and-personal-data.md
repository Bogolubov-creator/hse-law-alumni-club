# Поддержка, маскот и персональные данные

Состояние на 08.09.2026: поддержка реализована для локальной проверки. Соответствие всего production-портала 152-ФЗ не подтверждено: оператор, его полномочия, хостинг и обработчики не определены пользователем. Запрошены название оператора и контакт для обращений. Не следует публиковать унаследованные реквизиты НИУ ВШЭ как установленный факт.

## Работающая поддержка

Адрес: http://localhost:5274/support (канон V3; прежний /v2/support редиректит). Обратная связь внутри сайта: тема, текст, отдельное согласие, код доступа, ответ администратора, дополнительные сообщения, закрытие и удаление обращения. Никакие письма посетителям или внешние сообщения не отправляются. Ответ проверяется кнопкой на странице обращения.

### FAQ-бот без ПД (ДПО + клуб)

Угловая кнопка «Поддержка» (SupportDock) открывает панель ClubSupportBot, а не сразу форму тикета. Бот отвечает только цитатами и данными сайта: FAQ (`public/content/bot-faq.json`) и каталог программ (живой `GET /api/programs`, fallback `public/content/bot-catalog.json`). Логика match/reply перенесена из [SergeyBuzanov/dpo-pravo-hse](https://github.com/SergeyBuzanov/dpo-pravo-hse) (`bot-match` / `bot-reply`). LLM не используется. Бот не собирает персональные данные: нет полей ФИО, email, телефона и журнала вопросов. Темы без ответа на сайте (оплата, счёт, рассрочка и т.п.) и кнопка «Написать человеку» ведут на `/support` – живые тикеты с согласием. На `/support` и `/admin` dock скрыт.

Email, ФИО и телефон не обязательны и не собираются отдельными полями. Поле сообщения может содержать ПД, поэтому доступ ограничен. Передача сведений о третьих лицах, паспортов, платёжных реквизитов и чувствительных сведений не запрашивается. Поддержка не заменяет формальную идентификацию заявителя при обращении за данными другого аккаунта.

Ключ доступа: случайные 256 бит, в БД только SHA-256, в запросах отдельный заголовок, в URL не передаётся. Браузер помнит последний код в sessionStorage текущей вкладки; для обращения после закрытия вкладки пользователь сохраняет код самостоятельно. Код не связывается с клубным профилем. Это отдельная переписка: удаление профиля само по себе не удаляет анонимное обращение, для него предусмотрена отдельная кнопка.

Таблица club_support_tickets не выставлена как публичная коллекция Directus. Чтение и ответ сотрудника доступны только full admin; editor получает 403. Список разбит на страницы по 30. Сообщения ограничены 4000 символами, переписка – 50 сообщениями. Есть ограничения частоты; первоначальное создание идемпотентно. Ответы не кэшируются. Сообщения и ключи не включаются в журналирование ошибок поддержки или Sentry. Действия администратора аудируются без текста переписки.

Сохраняются точный текст согласия, его SHA-256, время и связь с обращением. Уведомление cookies не заменяет согласия. Локальный проект отдельного согласия: /v2/support/consent. Production-приём новых обращений закрыт по умолчанию, до явного включения и заполнения реквизитов оператора.

Тестовый срок хранения – 30 дней после сообщения или закрытия, это настройка проекта, а не универсальный срок 152-ФЗ. Истёкшая переписка сразу недоступна через API, удаляется при старте и ежедневной очистке. Кнопка отзыва немедленно удаляет действующую запись. Сроки резервных копий и подтверждение уничтожения в production требуют отдельного регламента оператора; SQL DELETE не доказывает уничтожение копий.

## Запуск

Из рабочей папки /Users/macbook/alumni-staged-refinement применить добавочную миграцию только к изолированной БД:

```sh
docker compose --env-file /Users/macbook/alumni-staged-evidence/local.env -f /Users/macbook/alumni-staged-evidence/compose.yaml exec -T postgres psql -U alumni_staged -d alumni_staged < apps/api/migrations/20260908-support.sql
```

Переменные API: SUPPORT_ENABLED, SUPPORT_OPERATOR_NAME, SUPPORT_OPERATOR_ADDRESS, SUPPORT_OPERATOR_CONTACT, SUPPORT_RETENTION_DAYS. Заполнение переменных само по себе не подтверждает выполнение организационных обязанностей. Для локальной разработки используется APP_ENV=development и только синтетические данные. Для production сохраняется SUPPORT_ENABLED=false, пока не завершена проверка ниже.

Для трансграничной передачи, безопасности, уничтожения и уведомления регулятора установлены самостоятельные требования. ## Подготовка маскота и движение

Компонент MascotSlot и конфигурация apps/web/src/config/mascot.ts предусматривают отдельные локальные файлы для главной и поддержки. В главной остаётся предусмотренная сеткой область 330px на широком экране; до получения маскота в ней Фемида. Кнопка поддержки имеет место под компактный образ. Если файл не найден, работает прежняя иллюстрация/иконка. Внешние URL не подключаются.

Нужны сам маскот, право использования, статичный вариант с прозрачностью и, если есть, отдельный анимационный вариант. Для будущей анимации потребуется статичный fallback при prefers-reduced-motion; пока анимированные файлы не подключались. Поддержка открывается по действию, автоматических всплытий нет.

В текущей V2 нет автоматической анимации первого экрана. Остались переходы состояния и hover 140–200ms, у кнопки поддержки 160ms с отключением по prefers-reduced-motion. В унаследованной V1 есть бегущая строка и эффекты загрузки/плеера. Политика движения разных поверхностей не выдаётся за одинаковую.
