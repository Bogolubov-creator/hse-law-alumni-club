# Выбор архитектуры – 08.09.2026

Выбран вариант 2: React/Vite + Fastify/Directus/PostgreSQL текущего клуба, с переносом пользовательских результатов и композиционных решений Kimi. Это решение принято после сборки обеих версий, запуска реальных изолированных баз, просмотра desktop/mobile и сохранения заявок с повторным чтением в кабинете.

## Три варианта

| Вариант | Польза | Работа и неопределённость |
|---|---|---|
| Kimi целиком | Единый интерфейс, самостоятельные страницы товара/события, ясные разделы кабинета | Помимо исправления подтверждённых расчётных/транзакционных ошибок нужны собственная авторизация, почта, восстановление, подкасты/подписки/платежи, рефералы/друзья/интересы, Vision/PWA/push, перенос UUID и денежных единиц. Наибольшая работа по данным и правам; собственный запуск каталога уже доказан, поэтому зеркало не аргумент против |
| Текущий портал + решения Kimi | Сохраняются данные, оплаченные права, direct slug, серверные сценарии; интерфейс можно существенно изменить | Нужно исправить дубли заявок/остатки и подтверждённые UI-дефекты, добавить недостающие адресуемые детали, сравнение/URL-фильтры и навигацию. Объём ограничен существующими контрактами |
| Интерфейс Kimi + сервер клуба | Позволяет сохранить цельный внешний вид B | Практически все страницы B обращаются к tRPC с числовыми ID и рублями; A использует REST/UUID/копейки, иной профиль/состояния. Помимо адаптеров всё равно нужны отсутствующие экраны. Сопоставимый визуальный результат достигается переносом конкретных компонентов без второго клиентского контракта |

Определяющий аргумент – полнота действующих сценариев и сохранность данных/подписок. Не число тестов и не привычность стека. Крупного миграционного эксперимента не требуется для этого решения: выбор не основан на предположении о невозможности сопряжения API.

## Что переносится

Из B: адресуемые детали товара и события, три измерения фильтров ДПО, понятная навигация кабинета и подробный состав заявки, композиционные приёмы. Из A: договоры API, данные CMS, авторизация, подкасты/подписки/платежи, социальные функции, Vision/PWA. Из отдельного ДПО: сравнение до трёх программ с URL, общий источник данных и московская дата.

## Данные и откат

Никаких пользовательских данных в MySQL не переносим. Обе исходные версии сохранены. Все изменения только в отдельной ветке и тестовой базе; откат UI через исходный снимок, миграции схемы только добавочные с отдельным журналом. Предыдущие рабочие пути сохраняются. В production ничего не опубликовано.
