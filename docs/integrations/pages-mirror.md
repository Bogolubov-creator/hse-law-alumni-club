# Статическое зеркало на GitHub Pages

Зеркало экспортируется из Jinja2-шаблонов без API и базы данных. Публичные
разделы, демо-кабинет и панель офиса используют отдельные фикстуры.
Регистрация, отправка заявки и сохранение серверных правок отключены.

Репозиторий: [club-pravo-hse-mirror](https://github.com/Bogolubov-creator/club-pravo-hse-mirror).
Адрес: [Pages-зеркало](https://bogolubov-creator.github.io/club-pravo-hse-mirror/).
Текущий исходный коммит записывается в `version.json` при публикации.

## Локальная сборка

Из корня проекта:

```bash
uv sync --directory frontend --frozen
uv run --directory frontend python -m club_web.mirror --output /tmp/club-mirror --base /
uv run --directory frontend python -m http.server 4173 --bind 127.0.0.1 --directory /tmp/club-mirror
```

Откройте `http://127.0.0.1:4173/`. Для GitHub Pages укажите базовый путь
`--base /club-pravo-hse-mirror/`. Экспортёр создаёт HTML каждой страницы,
`404.html`, фрагменты, manifest, `.nojekyll`, статические данные и календарные файлы.

## Поведение

- Демо-кабинет и офис показывают синтетические данные. Доступ к ним не является
  серверной авторизацией.
- В кабинете есть коллекция достижений с условиями и демонстрационным прогрессом.
  Реальные посещения, заказы и обучение из этого просмотра не следуют.
- Опросы видны в `/lk/#polls` и `/admin/polls/`. Вопросы, голоса и итоги вымышлены;
  создание, запуск, закрытие и отправка голоса отключены.
- Корзина хранится в `sessionStorage` вкладки; можно добавить, изменить и удалить
  позиции. Отправка заявки отключена.
- Поиск, фильтры каталога и дайджеста, сравнение и календарь работают локально.
- Сохранённые материалы используют хранилище браузера.
- Переключатель «Мобильный просмотр» в верхней полосе открывает `/tg/?pwa=1`.
  На компьютере интерфейс ограничен колонкой 430 px, на телефоне занимает экран.
  Нижние вкладки и меню сохраняют мобильный режим при переходах; «Обычный сайт»
  возвращает главную и выключает предпросмотр. Режим работает прямо в браузере
  без установки приложения или входа в Telegram. Панель офиса открывается на
  всю ширину экрана; выбранный режим открытой части сайта сохраняется.
- PWA и Telegram-предпросмотр используют тот же интерфейс; для PWA есть `?pwa=1`.
- Семь подкастов подключены к ранее опубликованным публичным MP3. Деморежим
  подписчика обозначен явно: [поведение аудио](podcast-mirror-audio.md).
- Страницы имеют `noindex`. Данные и помощники зеркала не входят в рабочий web-образ.

## Обновление

Workflow в репозитории зеркала получает выбранный `source_ref`, устанавливает
Python-зависимости по lockfile, выполняет браузерные проверки зеркала и офиса,
обновляет дайджест и запускает экспортёр.
Затем публикуется каталог HTML и статики. Проверяют результат workflow,
`version.json`, ссылки и пользовательские сценарии опубликованного сайта.

После успешного CI `main` запустите публикацию по полному 40-символьному SHA:

```bash
mirror_revision=$(gh api repos/Bogolubov-creator/hse-law-alumni-club/commits/main --jq .sha)
gh workflow run deploy-pages.yml --repo Bogolubov-creator/club-pravo-hse-mirror -f source_ref="$mirror_revision"
```

Дождитесь успешного задания `deploy` в
[workflow публикации](https://github.com/Bogolubov-creator/club-pravo-hse-mirror/actions/workflows/deploy-pages.yml).
Значение `source_commit` в [version.json](https://bogolubov-creator.github.io/club-pravo-hse-mirror/version.json)
должно совпасть с выбранным SHA. Затем откройте главную, ДПО, подкасты, изменения
в праве, кабинет с достижениями и `/admin/polls/` на компьютерной и мобильной
ширине. Проверьте отсутствие ошибок консоли, битых ресурсов и отправки данных.
Для возврата к прежнему зеркалу повторно запустите workflow с полным SHA
предыдущей проверенной публикации.

Импорт дайджеста описан в [LegisDigest](legis-digest-integration.md).
Проверка настоящих сервисов выполняется по [runbook](../operations/deploy-runbook.md).
