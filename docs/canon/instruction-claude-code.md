# Инструкция для Claude Code — функционал и бэкенд клубного портала

> Вставьте этот документ целиком в начало сессии Claude Code. Затем просите модули по фазам.
> В каждой новой сессии снова вставляйте этот документ — он держит архитектурный контекст.

## Роль и задача
Ты — ведущий инженер проекта **«Клуб выпускников "Бизнес и право" НИУ ВШЭ»**.
Реализуешь весь функционал и бэкенд под фронт от Claude Design. **Оплаты в проекте нет**:
витрины ведут к корзине и **оформлению заказа с контактами** (заявка для связи), которую офис
обрабатывает вручную. Работаем поэтапно. Перед кодом каждого модуля — короткий план файлов и эндпоинтов.

## Архитектура
```
Монорепо (pnpm workspaces):
  apps/web      — Vite + React + TS + Tailwind (фронт от Claude Design)
  apps/api      — Fastify + TS + zod (кастомная логика)
  packages/shared — типы и zod-схемы
  infra         — docker-compose.yml, Caddy

Бэкенд правды + админка: Directus + PostgreSQL (self-hosted на VPS).
  Directus закрывает: CMS (страницы, новости), каталоги (программы, товары),
  профили выпускников, реестр баллов, достижения, роли/права, авторизацию, и
  готовую админку для учебного офиса.
Кастомный API (apps/api) закрывает то, чего нет в CMS:
  корзина, оформление заказа с контактами, уведомление офиса о новой заявке,
  движок геймификации, cron-decay, авторизация mini-app.
Деплой: docker-compose на VPS (postgres, directus, api, caddy для TLS, web как статика).
```
**Стек по умолчанию** — Directus + Fastify (TS), как в стеке заказчика. Если попросят Python —
заменить apps/api на FastAPI, остальное без изменений.

## Правила
- TypeScript строгий, **zod** на всех входах. Секреты — только через `.env`, ничего не хардкодить.
- Валидация роли на каждом эндпоинте. Все ответы — рабочий код + команды запуска + мини-тест.
- **Никаких платёжных интеграций и карточных данных** — заказ = заявка с контактами, без денег.
- Каждый модуль — с критериями приёмки.

## Роли и доступы
- **guest** — публичное чтение, корзина, оформление заявки.
- **alumni** — ЛК, скидка по уровню, свои заказы, рефералка.
- **editor (учебный офис)** — CMS, новости, витрины, заявки/заказы, верификация, ручные баллы/скидки.
- **admin** — всё + правила достижений/уровней, роли.

## Модули по фазам

**Фаза 0 — каркас.**
Подними монорепо и `infra/docker-compose.yml` (postgres, directus, api, caddy). Дай `.env.example`,
README с командами. Настрой Directus: коллекции и поля по схеме выше, роли guest/alumni/editor/admin,
сервисный токен для apps/api.
*Приёмка:* `docker compose up` поднимает стек, админка Directus открывается, тестовый логин выпускника проходит.

**Фаза 1 — публичный сайт + CMS.**
Эндпоинты/запросы к Directus для страниц (`pages.blocks_json`) и новостей. Рендер блочных страниц
на apps/web, лента новостей и страница поста. Редактор страниц/новостей — средствами админки Directus.
*Приёмка:* редактор меняет контент страниц и новостей без участия разработчика.

**Фаза 2 — геймификация.**
Движок баллов и уровней в apps/api: `points_ledger` как источник правды, пересчёт `points_cached`/
`level_cached`. Уровни: Выпускник 0/5%, Друг клуба 200/10%, Знаток 500/15%, Амбассадор 1000/20%.
Эндпоинты: `POST /points` (начислить с reason), `GET /me/level`, `GET /me/ledger`. Триггеры достижений
по `rule_json` («Знаток» = 3 завершённые программы и т.п.). **Cron-decay** (node-cron): раз в месяц
−15% за неактивность; при понижении — событие «просел». Идемпотентно, с логом.
*Приёмка:* начисление меняет уровень и скидку; decay корректно понижает; «Знаток» открывается на 3-й программе. Юнит-тесты на расчёт уровня и decay.

**Фаза 3 — витрины, корзина, заказ с контактами (без оплаты).**
- Корзина: позиции из двух витрин (`type: dpo|merch`), `GET/POST/PATCH/DELETE /cart`.
- Оформление заказа: `POST /orders` — собрать контакты (ФИО, телефон, email, способ получения,
  адрес для доставки мерча, комментарий, согласие на обработку ПДн), рассчитать `member_discount`
  (level + personal) как справочную скидку, создать заказ со статусом `new`, присвоить `number`.
- **Уведомление офиса** о новой заявке: email и/или сообщение в Telegram-бот офиса (через .env-токен).
  Письмо-подтверждение заявителю с номером заявки.
- Эндпоинты заказов для ЛК (`GET /me/orders`) и для админки; смена статусов new → in_progress →
  confirmed → done / canceled.
*Приёмка:* оформление создаёт заказ со статусом `new`, офис получает уведомление, заявитель — подтверждение, скидка показана справочно. Денежных операций нет.

**Фаза 4 — админ-операции.**
Бизнес-операции поверх Directus/apps/api: верификация выпускника (активирует ЛК), ручное начисление
баллов и назначение персональной скидки, обработка заявок/заказов (смена статуса, заметки), CRUD витрин.
*Приёмка:* офис ведёт верификацию, баллы, скидки и заявки сам, без разработчика.

**Фаза 5 — mini-app.**
Собрать apps/web как Telegram Mini App и «Макс» mini-app. Вход через Telegram `initData`
(валидация подписи на api) и через «Макс» (web-app API / Госуслуги). Рефералка: deep-link с кодом
приглашающего; при верификации приглашённого — `+80` баллов рефереру. Кнопки шаринга программы/товара
в Telegram и «Макс».
*Приёмка:* запуск из мессенджера авторизует выпускника; рефералка начисляет баллы.

## Порядок работы (поэтапно)
Идём строго по фазам 0 → 5, не начиная следующую, пока текущая не прошла приёмку. После каждой фазы —
короткий отчёт: что сделано, как запустить, что проверить.
