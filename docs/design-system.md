# Дизайн-система

Справочник по токенам, примитивам и компонентам. Решения и их обоснование – в
[DESIGN.md](../DESIGN.md); здесь только то, что нужно, чтобы писать код и не
разъехаться с остальным сайтом.

**Главное правило.** Компонент просит токен, а не значение. `var(--c-accent-text)`,
а не `#c24009`; `var(--t-caption)`, а не `12`. Единственный файл, где встречается
hex, – [`tokens.css`](../apps/web/src/styles/tokens.css). Единственный файл, где
описан вид действия, поля и подписи, – [`primitives.ts`](../apps/web/src/styles/primitives.ts).

## 1. Токены

`apps/web/src/styles/tokens.css`, 66 определений в двух слоях.

**Слой 1 – палитра (`--p-*`, 19 штук).** Только там живут hex.
**Слой 2 – семантика (`--c-*`, 21 штука).** Компонент обращается сюда.
Тёмная тема – подмена значений слоя 2, а не правка компонентов.

Обращаться к слою 1 из компонента запрещено: `--p-ohra` не отвечает на вопрос
«охра здесь текст или заливка», а от этого зависит, какой тон брать.

### Цвет: заливка и текст – разные токены

Тон, годный как заливка, почти никогда не годится как текст. Это не стиль, это
арифметика: у мелкой моно-подписи требование 4,5:1.

| Смысл | Заливка | Текст | Контраст текста на кости |
|---|---|---|---|
| акцент | `--c-accent` | `--c-accent-text` | 4,74:1 |
| подтверждено | `--c-ok` | `--c-ok-text` | 5,96:1 |
| ошибка, отказ | `--c-danger` | `--c-danger-text` | 5,53:1 |
| статус, уровень | `--c-status` | `--c-status-text` | 4,98:1 |

Взять заливочный тон как текст – самая частая ошибка в этом проекте: так уже
проваливались зелёный (3,94:1), кармин (2,93:1) и латунь (2,37:1).

### Поверхности и текст

| Токен | Роль |
|---|---|
| `--c-bg` / `--c-bg-raised` / `--c-bg-sunken` | фон страницы / приподнятый блок / утопленный |
| `--c-text` / `--c-text-2` / `--c-text-3` | основной / вторичный / подписи |
| `--c-line` | разделитель: декоративный, планка 3:1 к нему не применяется |
| `--c-line-control` | **контур элемента управления**: 3,52:1 на кости, 4,32:1 на графите |
| `--c-line-strong` | линия бланка под данными реестра |
| `--c-on-accent` | текст на охряной заливке (тёмный, 5,12:1) |
| `--c-anchor` | институциональный синий: переходы на hse.ru |

### Типографика

| Токен | Значение | Где |
|---|---|---|
| `--f-display` | HSE Slab, **только 900** | титул страницы |
| `--f-head` | HSE Sans 600/700 | заголовки разделов |
| `--f-body` | HSE Sans 400 | текст |
| `--f-data` | системный моно | данные реестра, подписи |
| `--t-h1` | `clamp(32px, 6vw, 60px)` | титул главной |
| `--t-h1-page` | `clamp(27px, 3.2vw, 40px)` | титул витрины и внутренней страницы |
| `--t-h2` / `--t-h3` | `clamp(28…40)` / `clamp(22…28)` | разделы |
| `--t-lead` | `clamp(17px, 1.6vw, 20px)` | лид под титулом |
| `--t-body` / `--t-small` | 16 / 14 | текст |
| `--t-caption` / `--t-micro` | 12 / 12 | подписи; **12px – дно шкалы** |
| `--tr-data` | `0.16em` | разрядка моно-подписей |

У HSE Slab есть только 400 и 900. Указывать 600/700/800 нельзя: браузер
синтезирует начертание и размазывает штрихи.

### Форма, ритм, движение

| Токен | Значение | Где |
|---|---|---|
| `--r-sm` / `--r-md` / `--r-lg` | 8 / 12 / 18px | действие / поле и кнопка / панель |
| `--rh-head-top` / `--rh-head-bottom` | `clamp(26…44)` / `clamp(16…24)` | шапка витрины |
| `--rh-section` | `clamp(40…72)` | между секциями |
| `--container` | 1180px | ширина полосы набора |
| `--dur-fast` / `--dur-base` | 140 / 200ms | состояния / переходы |
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | всё движение |

`--space: 4px` объявлен, но не используется: отступы внутри блоков ставятся
числами. Это известный пробел, см. §5.

## 2. Примитивы стиля

`apps/web/src/styles/primitives.ts` – единственное определение на весь проект.
Импортируют и витрины (через `v2/Shell.tsx`), и кабинет, и админка.

| Примитив | Что задаёт | Варианты |
|---|---|---|
| `mono` | моно + табличные цифры | – |
| `disp` | заголовочный гротеск | – |
| `pageTitle` | титульная плита, вес 900 | – |
| `label` | моно-подпись капсом, третичный цвет | – |
| `action` | действие: охра, тёмный текст, `9px 15px` | `actionGhost` – обводка вместо заливки |
| `field` | поле ввода, просторное, во всю ширину | `fieldCompact` – плотное, для админки |

Разница `field` / `fieldCompact` **осознанная**: у кабинета ввод с телефона
(плотность 7), у панели офиса – с клавиатуры и плотность выше. Все прочие
различия между поверхностями были расхождениями, а не решениями, и сведены.

### Действие (`action` / `actionGhost`)

Единственный акцент на весь проект. Заливка – только у действия, которое
двигает человека вперёд: «В корзину», «Отправить заявку», «Вступить в клуб».

| Вариант | Когда |
|---|---|
| `action` | главное действие экрана. **Одно на экран.** |
| `actionGhost` | второстепенное рядом с главным: «Отмена», «Подробнее» |
| ссылка `--c-anchor` | уход на hse.ru и другие внешние переходы. Не кнопка |

| Состояние | Вид | Поведение |
|---|---|---|
| обычное | охра, тёмный текст 5,12:1 | – |
| фокус | обводка 3px `--c-accent`, отступ 2px | класс `foc` обязателен |
| наведение | `--c-accent-text` у ссылок навигации | у кнопок наведения нет: витрина не мигает |
| недоступно | прозрачность 0,45, курсор `not-allowed` | правило глобальное, `disabled` достаточно |
| занято | `disabled` на время запроса | текст кнопки не меняется |

| ✅ Так | ❌ Не так |
|---|---|
| `<button className="foc tap" style={action}>` | собирать кнопку инлайном из `background: var(--c-accent)` |
| охра у одного действия на экране | охра и синяя заливка рядом |
| `disabled={m.isPending}` | блокировать кликом и молчать |

```tsx
import { action, actionGhost } from "../styles/primitives.js";

<button className="foc tap" style={action} disabled={add.isPending} onClick={submit}>
  В корзину
</button>
<button className="foc tap" style={actionGhost} onClick={close}>Отмена</button>
```

### `BlankField` – сигнатура клуба

Тонкая линия с моно-подписью под ней: типографика официального бланка.

**Ставится только там, где под линией настоящие данные реестра.** Это не
разделитель и не украшение: как только `BlankField` появляется вокруг
произвольного текста, сигнатура перестаёт что-либо значить.

```tsx
<BlankField label="в каталоге 21 · актуальный набор 21">
  <p>Каталог программ дополнительного образования факультета.</p>
</BlankField>
```

### `ShowcaseHead` – шапка витрины

Надзаголовок, титул плитой, лид и счётчик записей. Даёт странице ровно один `h1`
и единый вертикальный ритм на всех витринах.

| Свойство | Тип | Обяз. | Описание |
|---|---|---|---|
| `eyebrow` | `string` | да | моно-надзаголовок: «витрина · дпо» |
| `title` | `string` | да | титул страницы, `--t-h1-page` |
| `lead` | `string` | да | объяснение в одно предложение |
| `count` | `string` | нет | счётчик записей; включает `BlankField` |

Титул `--t-h1` (крупнее) – только у главной. Витрина, корзина и внутренние
страницы берут `--t-h1-page`: иначе иерархии страниц не остаётся.

### `Modal`

| Свойство | Тип | По умолчанию | Описание |
|---|---|---|---|
| `onClose` | `() => void` | – | вызывается по Esc и клику по фону; своей кнопки закрытия у модалки нет – её рисует вызывающий экран |
| `labelledBy` | `string` | – | id заголовка внутри; обязателен, если заголовок есть |
| `maxWidth` | `number` | 460 | ширина коробки |

Клавиатура: `Esc` закрывает, `Tab` не выходит за пределы, фокус возвращается на
элемент, с которого открыли. Экранный диктор объявляет как диалог.

### `MobileTabs`

Нижняя навигация v2: главная, ДПО, мерч, корзина, кабинет. Высота вкладок объявлена
в `index.css` как `--tabs-h` и прибавляется к нижнему отступу оболочек, чтобы вкладки
не накрывали контент и cookie-баннер. Активная
вкладка помечена `aria-current="page"`, а не только цветом.

## 4. Правила, которые держат систему

1. **Hex – только в `tokens.css`.** Исключения ниже, все три названы поимённо.
2. **Заливочный тон не ставится как цвет текста.** Для текста есть `-text`.
3. **12px – дно шкалы.** Моно-подпись капсом с разрядкой мельче нечитаема.
4. **Титульная плита – только 900.**
5. **Один акцент на экран.** Второй акцент означает, что действий два главных, –
   значит, экран спроектирован неверно.
6. **`className="foc"` на каждом интерактивном элементе.** Без него не видно фокус.
7. **`className="tap"` там, где палец.** Даёт 44px на сенсорном вводе, не трогая
   плотность под мышью.
8. **`h1` на странице один.**
9. **Поле и полая кнопка обводятся `--c-line-control`, а не `--c-line`.** По
   1.4.11 контур, по которому элемент вообще опознают, обязан давать 3:1.
   Разделитель списка под это не подпадает и остаётся тихим.
10. **Каждая оболочка даёт `<main id="main">`** – к нему ведёт ссылка-пропуск.
11. **Версия для слабовидящих доступна с любой ширины экрана.** Она жила только
    в десктопной строке, и на телефоне включить её было нечем.

Проверяется двумя тестами.

[`design-language.spec.ts`](../apps/web/e2e/design-language.spec.ts) – контраст
текста и нижняя граница шкалы на семи публичных экранах в обеих темах, иерархия
титулов, гарнитура и вес титула, отсутствие заливки у внешней ссылки.

[`a11y.spec.ts`](../apps/web/e2e/a11y.spec.ts) – WCAG 2.1 AA: ссылка-пропуск
первой остановкой табуляции, контур элементов управления в обеих темах,
ориентиры и заголовки, и отдельно версия для слабовидящих: обводка фокуса во
всех трёх схемах ГОСТ, `foc` на всех органах панели, непрозрачный фон диалога,
доступность режима с телефона. Клавиатурные проверки идут только в
desktop-проекте: WebKit не двигает фокус по Tab без Full Keyboard Access, и это
модель ввода движка, а не дефект страницы.

## 5. Известные исключения и долги

**Исключения – так и должно быть:**

- `html[data-vis-scheme="bw|wb|bb"]` в `index.css` держит фиксированные hex.
  Это режим для слабовидящих по ГОСТ: чёрное на белом, белое на чёрном, синее на
  бежевом. Значения заданы требованием, темизировать их нельзя.
- `field` и `fieldCompact` – разная плотность у кабинета и панели офиса.

**Долги, по убыванию цены:**

| Что | Размер | Цена промедления |
|---|---|---|
| Кнопка собрана инлайном в 19 местах: 9 разных `padding`, 5 кеглей | v2 целиком | правка кнопки требует 19 правок и уже разошлась |
| `lk-theme.ts` – **вторая система токенов**: 41 hex в объекте React-контекста со своим переключателем светлой и тёмной темы | `Lk.tsx`, `Profile.tsx`, `LkShell.tsx` | правка `tokens.css` до кабинета v1 не доходит вообще |
| `v1` и мобильная оболочка: 600 hex, `var()` – ноль | `pages/*.tsx`, `mobile/` | правка палитры в v2 не доходит до v1 |
| Общие компоненты (`Toast`, `ErrorBoundary`, `InstallPrompt`, `SiteShell`, `CookieBanner`) – 27 hex | 5 файлов | они рисуются поверх v2 и не следуют его теме |
| Отступы: 702 числа, `--space` не используется | весь проект | шкалы отступов нет, ритм держится вручную |
