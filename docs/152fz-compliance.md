# Соответствие 152-ФЗ «О персональных данных»

Портал обрабатывает ПДн выпускников (ФИО, контакты, год выпуска, образование,
активность). Ниже – что реализовано в коде и что нужно сделать оператору
организационно (кодом не закрывается).

## Реализовано в платформе

| Требование | Как закрыто | Где |
|---|---|---|
| Согласие на обработку ПДн (получение) | Обязательный чекбокс, проверка на сервере (`z.literal(true)`), пустой по умолчанию | `auth.ts` (register), `orders.ts` |
| **Учёт (доказательство) согласия** | При регистрации сохраняются `consent_at` (когда) и `consent_version` (редакция политики) | `alumni.consent_at/consent_version`, `auth.ts` |
| Политика обработки ПДн (публикация, ст. 18.1) | Страница `/privacy` + `/confidential` + реквизиты оператора | `apps/web/src/pages/legal.tsx` |
| **Право на доступ (ст. 14)** | Самостоятельная выгрузка всех своих данных одним JSON | `GET /me/export`, кнопка «Скачать мои данные» в профиле |
| **Право на удаление / отзыв согласия** | Самоудаление (с подтверждением) + удаление офисом; обезличивание ПДн, удаление аккаунта входа, гашение сессий | `POST /me/delete`, `POST /admin/members/:id/anonymize`, `lib/anonymize.ts` |
| **Срок хранения / ретенция** | Крон 04:00: заявки старше `ORDER_RETENTION_DAYS` (3 года) обезличиваются, аудит старше `AUDIT_RETENTION_DAYS` (1 год) удаляется | `lib/retention.ts`, cron в `server.ts` |
| **Минимизация / трансграничная передача** | В Telegram (зарубежный сервис) ПДн заявителей НЕ уходят – только номер заявки; контакты офис смотрит в админ-панели (РФ) | `lib/notify.ts` |
| Cookie: информирование + свободный выбор (ст. 9) | Баннер с «Только необходимые» / «Принять все», ссылка на политику, повторный выбор из подвала; аналитика не грузится без «all» | `components/CookieBanner.tsx`, `lib/cookie-consent.ts` |
| Меры защиты (ст. 19) | HTTPS/HSTS, строгий CSP, API и БД только на localhost, разграничение ролей, локаут перебора, аудит-лог, ревокация JWT | `infra/Caddyfile`, `server.ts`, `lib/security.ts`, `lib/audit.ts` |
| Шифрование резервных копий | AES-256 бэкап + проверка восстановимости | `scripts/backup-db.sh`, `scripts/backup-verify.sh` |
| Передача платёжному сервису | Карту не храним; данные вводятся на стороне ЮMoney (ЮKassa) | политика, `lib/yookassa.ts` |

## Организационные шаги оператора (кодом не закрываются)

Обязательно ДО запуска на проде:

1. **Локализация БД в РФ (ст. 18.5).** Развернуть на VPS в РФ (Selectel/FirstVDS/др.).
   Задать `PUBLIC_URL=https://<домен>`, `APP_ENV=production` (включает fail-fast небезопасной
   конфигурации). `VITE_SITE_URL`/`VITE_DIRECTUS_URL` инлайнятся в web-бандл на сборке –
   при смене домена web пересобрать.
2. **Уведомление в Роскомнадзор об обработке ПДн (ст. 22).** Подать уведомление
   оператора через портал РКН (или подтвердить, что подпадает под исключение).
3. **Назначить ответственного за организацию обработки ПДн (ст. 18.1 ч.1 п.1)** и
   утвердить внутренние документы: Политику, Положение об обработке и защите ПДн,
   перечень ПДн, модель угроз, приказ о допуске.
4. **DPA/поручение обработки с ЮKassa** (если платежи включены) и фиксация её как
   обработчика в политике.
5. **Согласие на трансграничную передачу** – не требуется: платформа ПДн за рубеж
   не передаёт (Telegram-уведомления обезличены). Если появятся зарубежные
   интеграции – получать отдельное согласие (ст. 12).
6. **Проверить реквизиты оператора** в `packages/shared/src/operator.ts` и на страницах `/privacy`, `/requisites` – оператор: АНО «Клуб выпускников факультета права НИУ ВШЭ», ОГРН 1257700005551, ИНН 9707041865 (сверка Rusprofile 10.09.2026: https://www.rusprofile.ru/id/1257700005551).
7. **Ретенция:** значения `ORDER_RETENTION_DAYS`/`AUDIT_RETENTION_DAYS` привести к
   утверждённым срокам; бэкапы выгружать на отдельное хранилище в РФ – задать
   `BACKUP_OFFSITE_REMOTE` (rclone-remote), тогда `scripts/backup-db.sh` копирует туда
   шифрованный дамп автоматически.

Обращения субъекта – по юридическому адресу оператора или через `/support` (тема «Персональные данные»), срок ответа 10 рабочих дней (см. политику).

**Стенс релиза без ЮKassa/VAPID:** допустим при живом SMTP и закрытом `SUPPORT_ENABLED`
до завершения оргпакета – см. [external-keys-checklist.md](external-keys-checklist.md)
(раздел «Стенс релиза»).

Порядок деплоя, отката, восстановления и ротации секретов – см. [deploy-runbook.md](deploy-runbook.md).

## Ключевые эндпоинты прав субъекта

- `GET /me/export` – получить копию своих данных (авторизованный выпускник).
- `POST /me/delete` `{confirm:"УДАЛИТЬ"}` – стереть данные / отозвать согласие.
- `POST /admin/members/:id/anonymize` – исполнение запроса на удаление офисом.
- Обращения субъекта также принимаются по юридическому адресу оператора или через `/support`
  (тема «Персональные данные»), срок ответа 10 рабочих дней.
