# Переход приложения на Python и FastAPI

## Решение

1 октября 2026 года владелец поручил перенести TypeScript-сервер на Python/FastAPI.
Затем владелец согласовал замену React на FastAPI + Jinja2 с минимальным
JavaScript. PostgreSQL, Caddy, дизайн и функции сайта сохраняются. Команды
bootstrap, управления сотрудниками и импорта также работают на Python.

## Совместимость

- Сохраняются прежние HTTP-контракты и роли alumni/editor/admin. Добавлены
  чтение текущей сессии офиса и ответы бота сайта через API.
- Таблицы, UUID, PHC-хеши, поколения сессий и имя тома uploads сохраняются.
- SQL-миграции дополняют существующую схему; перенос данных в новую БД не нужен.
- API проверяет актуальную роль и status в PostgreSQL. SSO/MFA-аккаунты не
  переводятся на локальный пароль.
- PHC-параметры прежнего Node Argon2 проверяются в обоих порядках `m,p,t` и `m,t,p`.
  Хеши при обновлении не переписываются.
- Справочники уровней, правил, достижений, интересов и FAQ находятся в общих JSON.
  Демо-каталог попадает только в отдельную сборку bootstrap и статическое зеркало.
- API работает в одном процессе Uvicorn. Внутренний планировщик asyncio заменяет
  node-cron; расписание, флаги и PostgreSQL-идемпотентность сохраняются.
- Загрузка и выдача аватаров используют Pillow. Одновременно допускаются две проверки Argon2 и одна обработка изображения;
  очереди ограничены при лимите контейнера 512 MiB.

## Сборка и обслуживание

Python 3.14.7, FastAPI 0.142.2 и зависимости закреплены в `uv.lock`.
Docker использует официальный Python на Alpine с закреплённым digest.
Собственные модули компилируются; исходники и инструменты сборки исключаются
из рабочего образа. UID 1000 сохраняет доступ к файлам прежней установки.

Прежние TypeScript-пакеты API, server-auth и команд оператора удалены.
React, TypeScript, Node.js и их сборщик исключены из проекта. Web формирует
HTML из Jinja2-шаблонов и читает контент через внутренний API. Браузерные
модули обслуживают интерактивные действия, плеер, PWA и Telegram. Статическое
зеркало экспортируется из тех же шаблонов с отдельными публичными фикстурами.
На Ubuntu установка выполняется через `sudo ./scripts/install.sh` с контейнерами.

## Проверка и откат

Проверки перечислены в [testing.md](../development/testing.md), результаты –
в [журнале](../operations/project-state.md). Изолированные проверки используют
синтетические данные, Mailpit и подменённые внешние провайдеры. Работа реальной
почты, оплаты и Telegram подтверждается отдельно при публичном запуске.

Обновление выполняется по [runbook](../operations/deploy-runbook.md). Перед ним
сохраняются согласованная копия БД/uploads и ID прежних образов. Схема совместима
с предшествующим API: при откате возвращаются совместимые API/bootstrap/web-образы, затем
проверяются readiness, вход и чтение данных. Рабочую БД и тома не удаляют.
