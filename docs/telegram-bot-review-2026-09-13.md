Бот: @pravohse_alumni_bot. Пользователь подтвердил отсутствие запущенного обработчика.
Токен проверен запросом getMe, в репозиторий и отчёт не сохранялся.

## Что подтверждено в Telegram

- Имя бота совпадает; webhook отсутствует, меню содержит start, points, calendar, help.
- Описание и короткое описание пустые. Основной Web App не назначен; меню имеет тип commands.
- После тестового сообщения пользователя определён единственный личный тестовый чат.
- Четыре ответа сформированы действующим кодом с локальным Directus QA и отправлены только туда: help (505 символов), points (195), calendar (298), FAQ по налоговому праву (1032). Telegram принял все четыре sendMessage.
- Это проверка чтения данных, форматирования и реальной отправки. Непрерывный polling/webhook и пользовательское чтение сообщений не подтверждены этим тестом. Очередь входящих сообщений не подтверждалась через offset.
- Реальная привязка аккаунта не выполнялась. Сценарий изменения telegram_id проверен на тестовой БД в памяти. Подписанное initData проверяется отдельными unit-тестами, а не живым Mini App.
- После теста процесс завершён; временный файл с токеном удалён. Постоянного обработчика по-прежнему нет. Меню Telegram автоматически не расширялось.

## Возможности и изменения

| Сценарий | Реализация и результат |
|---|---|
| /start | Приветствие, реферальная ссылка, привязка из кабинета по подписанному коду. Имя теперь экранируется для HTML |
| /points | Баллы, уровень и скидка только по Telegram отправителя. Для непривязанного профиля дана инструкция, для ожидающего проверки скрыты показатели |
| /calendar | До пяти будущих опубликованных событий, московское время, число записавшихся и собственная отметка участия |
| Свободный вопрос | Общая с сайтом база FAQ и опубликованный каталог ДПО; переход к поддержке при отсутствии ответа |
| /help | Полный список команд и ссылки |
| /cabinet, /dpo, /support | Добавлены прямые переходы к существующим разделам сайта. Они не создают отдельные хранилища профилей или обращений |
| Неизвестная команда | Вместо молчания объяснение и /help |
| Группы и каналы | Обработка отключена до любых чтений/изменений: личные баллы и привязка не попадают в общий чат |
| Webhook | Без TELEGRAM_WEBHOOK_SECRET endpoint закрыт даже в development; скрипт установки также требует секрет |
| Локальный polling | Больше не удаляет чужой работающий webhook: при его наличии или ошибке проверки запуск прекращается |

Команды, баллы, календарь, привязка, FAQ, Telegram initData, webhook и запрет конфликтного polling покрыты автоматическими проверками. Они используют тестовые токены и синтетические данные.

## Локальный запуск

Отдельная точка входа apps/api/src/telegram-local.ts запускает только бота, без HTTP и cron.
Сначала выполнить `pnpm --filter @club/api build` после сборки shared.
Далее из корня репозитория:

```sh
node --env-file=/absolute/path/outside-repo/bot.env apps/api/dist/telegram-local.js
```

Файл окружения хранится вне репозитория с правами 600. Обязательны DIRECTUS_URL,
DIRECTUS_SERVICE_TOKEN, AUTH_SECRET (от 32 символов), TELEGRAM_BOT_TOKEN,
TELEGRAM_POLLING=true, PUBLIC_URL. Для привязки AUTH_SECRET должен совпадать с API сайта.
Не указывать боевую CMS для экспериментальных тестов. PUBLIC_URL должен вести на
доступный пользователю сайт: localhost на телефоне не открывает сервер компьютера.
Процесс работает до Ctrl+C; при выключении или сне компьютера бот недоступен.
Старт регистрирует расширенное меню команд. Одновременно работает один обработчик.

## Что требуется для постоянного включения

1. Разместить API и Directus на постоянно доступном сервере, задать публичный HTTPS-адрес сайта. Статическое зеркало не исполняет серверный обработчик бота.
2. Выбрать один режим: webhook с секретом либо один polling-процесс. Привязать реальные профили только к тому же API/секрету, что использует сайт.
3. Повторить сквозную проверку с реальным тестовым аккаунтом: привязка из кабинета, /points после верификации, /calendar после записи на сайте, FAQ и переход к обращению.
4. Заполнить описание профиля после определения рабочего публичного адреса. Подключение Mini App и постоянных уведомлений не объявляется выполненным.
5. До масштабирования отдельно проверить повторную доставку update и временные сбои: текущий webhook отвечает до завершения обработки, polling не хранит offset между перезапусками; привязка состоит из нескольких записей, код не имеет срока действия. Эти механизмы требуют отдельного решения для надёжной доставки и отзыва ссылок.

Основание проверки методов: https://core.telegram.org/bots/api#getwebhookinfo и https://core.telegram.org/bots/api#getmycommands.
