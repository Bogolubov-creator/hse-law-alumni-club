# Telegram Mini App клуба: этап 1

Предыдущий пакет опубликован в codex/v3-backlog-polish, коммит 9f943e5.
Этап одобрен заказчиком для публикации в общей ветке и на зеркале.

## Основание

Изучены tg/index.html, js/tg-app.js и js/tg-core.js репозитория
https://github.com/itspecR/dpo-pravo-hse и присланный скриншот. Это референс
с компактными экранами, BackButton/MainButton и демонстрационной формой;
его данные и код не скопированы в клуб. API SDK сверено с
https://core.telegram.org/bots/webapps .

## Реализовано

- /tg открывает стартовый экран мини-приложения; режим сохраняется при переходах.
- Вкладка «Клуб» заменяет «Карту». PWA использует тот же старт: ближайшая встреча,
  кабинет и быстрые переходы. Афиша переиспользует существующий кэш событий.
- Кабинет, новости, события, ДПО, мерч, подкасты и помощь используют общие маршруты.
- Пять нижних вкладок, компактные заголовки каталогов, адаптация safe-area.
- Поиск ДПО остаётся на виду, дополнительные фильтры раскрываются по нажатию.
- На главной помощь открывается из карточки; плавающий маскот её не перекрывает.
- Официальный SDK загружается только при входе в mini-режим. CSP обоих Caddy
  разрешает скрипт Telegram. В обычном браузере есть выход из предпросмотра.
- В Telegram вызываются ready/expand и BackButton, события отписываются при выходе.
- Вход по кнопке отправляет initData на существующий /auth/telegram, сервер
  проверяет HMAC и связанный профиль. Клиент не доверяет initDataUnsafe.
- Ошибки привязки и срока сессии показаны в интерфейсе. Вход по почте сохранён.
- Сервер отклоняет дубли параметров, некорректный hash, дату из будущего,
  неверный ID и чрезмерно длинный initData. Секрет бота в клиент не передаётся.

## Проверка и пределы

Браузерный предпросмотр и SDK-заглушка проверяют навигацию, вход, отказ входа,
ready/expand, безопасные отступы и BackButton. Это не запуск в реальном Telegram.
В зеркале отправка заявок отключена, данные демонстрационные. Настройки бота
и webhook не менялись. Сервер ранее не развёрнут, токен в репозитории не хранится.

Сборки API и зеркала проходят. API: 295 тестов пройдено; 14 интеграционных
тестов отдельно пройдены на одноразовом PostgreSQL. Браузер: полный набор актуальных e2e; исторические staged-скрипты сравнения
старых кандидатов не входят в приёмку. Реальные корзина и поддержка проверяются
на изолированном QA API/CMS, остальные сценарии используют контрактные фикстуры.
Обход зеркала: 285 состояний (19 маршрутов, 5 ширин, сайт/PWA/Telegram),
без ошибок JavaScript и горизонтального переполнения.
Скриншоты получены из локальной сборки зеркала, ширина 390 px.

## Следующие этапы

1. Публикация одобренного /tg на зеркале из общей ветки и проверка опубликованных маршрутов.
2. Постоянное HTTPS-окружение API/CMS/БД и обработчика бота; перед живым запуском
   заменить текущую привязку профиля на одноразовый код с ограниченным сроком.
3. Кнопка открытия мини-приложения в боте и проверка на физических iOS/Android:
   запуск, возврат, клавиатура, сворачивание, вход, каталог, корзина и заявка.
4. Отдельная приёмка уведомлений и оплаты. Нативная MainButton и платежи Telegram
   этим этапом не подключаются: текущая нижняя навигация и действия форм сохранены.

Не считать этап 1 готовым production-запуском бота или установленным приложением.

## Приёмка релиза

- Сборка всех пакетов и сборка зеркала проходят.
- Unit: shared 78, web 43, API 295; интеграционные PostgreSQL 14.
- Полный Playwright CLI: 788 проверок, из них 18 пропущены из-за особенностей
  клавиатурной навигации WebKit (Full Keyboard Access).
- В финальном полном прогоне: 765 успешных, 5 падений. Исправлены ожидания
  перенесённого блока достижений и переполнение поля ссылки в Safari.
  Повтор всего профиля и дашборда на четырёх проектах: 32 успешных.
  Все 770 исполняемых сценариев прошли с учётом адресной перепроверки.
- Дополнительно: 285 состояний зеркала без ошибок JavaScript и переполнения.
- Реальные корзина и поддержка проверены только в alumni-local-qa. Тестовая
  программа «Тестовая программа CLI» существует только в этой локальной CMS.
- Локальные /ready, API, CMS и PostgreSQL отвечают успешно. Telegram и push
  не настроены; SMTP указан, health не выдаёт это за проверенную доставку.
- Browser plugin not available; использован установленный Playwright CLI.
