# Инвентаризация `MobileApp.tsx` – обоснование к снятию перехвата

**Дата:** 31.07.2026 · **Ветка:** `feat/frontend-v2` · **Статус:** обоснование, кода нет
**Решение по Q4:** вариант C (схлопнуть в одну адаптивную вёрстку), поэтапно.
**До вашего «да» ничего не сношу.**

## 1. Что это такое на самом деле

`apps/web/src/mobile/MobileApp.tsx` – 1058 строк, 87 КБ, 22 компонента.
Подменяет весь десктопный сайт при ширине `<768px` на маршрутах
`/`, `/news`, `/dpo`, `/podcasts`, `/merch`, `/cart`, `/dpo/:slug`, `/news/:slug`
(`App.tsx:31,38`).

Формально это «native app-shell по Claude Design». Фактически – **другая вёрстка тех же
экранов**. Проверил построчно, что именно делает её «нативной»:

| Признак «нативности» | Есть? | Проверка |
|---|---|---|
| Жесты (свайп, drag, pull-to-refresh) | **нет** | `onTouchStart\|onTouchMove\|onTouchEnd\|onPointerDown\|swipe\|useDrag\|PanResponder` → **0 совпадений** |
| Нижняя таб-навигация | да | `TabBar`, 44 строки, 5 табов |
| Липкая шапка с блюром | да | `HEADER`, 6 строк CSS |
| Safe-area под чёлку | да | `env(safe-area-inset-top)` – **но это же есть и в `index.css` для десктопной вёрстки** |
| Переходы между экранами | нет | обычный react-router |
| Оффлайн / нативные API | нет | – |

**Вывод:** «нативность» сводится к нижним табам и липкой шапке. Это 50 строк уникального
кода, ради которых существует 1058.

## 3. Что при схлопывании нельзя потерять

Три вещи, которые в мобильной версии сделаны **лучше** десктопной. Их надо забрать
в общую вёрстку, а не выбросить:

1. **`TabBar` – нижняя навигация.** На телефоне это правильнее бургера. Забираем как
   адаптивный компонент: `<768px` – нижние табы, шире – горизонтальная навигация
   `SiteShell`. Один компонент, две раскладки, а не две реализации сайта.
2. **`MobileHome` – «Карта выпускника» первым экраном.** Мобильная главная для
   вошедшего показывает не лендинг, а карточку статуса (`КАРТА ВЫПУСКНИКА`, выпуск,
   уровень, скидка). Это лучшее решение, чем десктопное «показать лендинг вошедшему».
   Логику забираем на все ширины.
3. **`MobilePodcastPlayer` – полноэкранный плеер.** Богаче десктопного инлайнового.
   Забираем как единый компонент плеера.

## 4. Что схлопывание чинит само по себе

**`/events` из мобильной оболочки недостижим.** Проверено:

- ссылок на `/events` в `MobileApp.tsx` – **0**;
- `/events` нет в `TABS` (там: Карта, Лента, ДПО, Подкасты, Мерч);
- `SiteShell` (у которого «События» есть в бургер-меню) внутри `MobileApp` **не рендерится** – 0 совпадений;
- `/events` не входит в `MOBILE_APP_ROUTES`, поэтому по прямому URL телефон получает
  десктопную страницу в узком вьюпорте.

То есть с телефона до страницы событий дойти нельзя никак, кроме как вручную набрать
адрес. Это незамкнутая петля из вашего списка, и в одной адаптивной вёрстке её
не существует по построению.

## 5. Цена сохранения (почему вариант B отклонён)

- Любая правка витрины, новости, корзины, программы или профиля делается **дважды**.
- Расхождения уже накопились: `/events` есть на десктопе и отсутствует на мобиле;
  плеер, достижения и история баллов реализованы по два раза и разойдутся дальше.
- Токены, ради которых затевается v2, придётся раскатывать по двум наборам экранов.
  При 779 инлайн-стилях в проекте 324 из них – именно в `MobileApp.tsx`.
- Аудитория – сотни человек, десятки активных. Параллельная кодовая база на пять
  экранов не окупается ничем.

## 6. Порядок работ (ваш, подтверждаю)

1. **Проход 1** – адаптив входит в план токенов и лейаута как первоклассное требование,
   а не «потом причешем». Вайрфреймы делаются сразу в двух ширинах.
2. **Проход 2** – десктопные экраны ложатся на токены, вёрстка адаптивная до 360px.
   `MobileApp.tsx` в это время живёт как есть, перехват работает.
3. **Отдельный PR** – снятие перехвата одним ревертируемым коммитом:
   удаление `mobileTakeover` из `App.tsx` и `MobileApp.tsx` из сборки.
   Файл остаётся в истории git, откат – `git revert` одного коммита.

Риск отката минимален: перехват – это одно условие в `App.tsx:38`.
