# Дашборд админки и состояние системы

Первый экран после входа: аналитический дашборд, период 7/30/90 дней,
просмотры, вступления, заявки, записи на события и прослушивания. График
просмотров доступен также таблицей. Популярные страницы ведут к полной
аналитике через общую кнопку. Ранее доступные задачи офиса сохранены ниже.
Используется существующий /admin/analytics, без нового сбора персональных данных.
Просмотры охватывают только пользователей с согласием; это не число посетителей.

## Контроль системы

GET /admin/system-health защищён requireAdmin, Cache-Control: no-store,
лимит 12 запросов в минуту. Проверки read-only, отправки сообщений нет.

- API: факт обработки текущего запроса.
- Directus: чтение одного id из levels сервисным токеном, timeout 3 секунды.
- База оформления: SELECT 1 через существующий пул, timeout запроса 3 секунды;
  ожидание соединения ограничено настройкой пула (5 секунд).
- Telegram: наличие токена, без утверждения о запущенном обработчике.
- Почта: наличие SMTP_HOST, доставка и соединение не проверяются.
- Push: наличие пары VAPID, доставка не проверяется.

Ответ содержит только результат, задержку и время запуска API; токены,
адреса подключений и исходные исключения наружу не выдаются. Ошибка одного
сервиса не уничтожает результаты остальных. Итог не объявляет всю систему
здоровой: внешние интеграции остаются непроверенными. Обновление ручное,
это текущий срез, не мониторинг SLA и не история инцидентов. Платёжный
провайдер, задачи cron и почтовая доставка требуют отдельной инструментализации.

На зеркале показатели демонстрационные, все сервисы «Не проверено».
Live-проверка постоянного сервера отсутствует: такого окружения пока нет.

## Проверки

Unit-тесты: успех, частичный отказ, неверный ответ CMS, отсутствие БД,
маскирование исключений и запрет выдавать наличие токена за работающего бота.
Новая ручка включена в проверки доступа администратора. Сборки API и зеркала
проходят. Браузерные сценарии Chromium/WebKit проверяют переключение периода,
отказ health, исчезновение устаревших статусов и успешный повтор.
Визуально проверены desktop 1440 px и mobile 390 px; переполнения нет.
