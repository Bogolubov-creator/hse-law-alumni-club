# Истории выпускников

На главной после блока о сообществе показаны три истории. В карточке находятся
фотография, имя, год или годы выпуска, профессиональная роль и короткое описание.
Нажатие на карточку открывает отдельную страницу с учёбой, биографией, этапами
карьеры и ссылками на официальные материалы НИУ ВШЭ. Все истории доступны
по адресу `/stories`.

## Как добавить или обновить историю

Общий источник – `data/alumni-stories.json`. Это редакционные публикации;
данные закрытых профилей участников не используются. Редактирование выполняется
в репозитории, формы управления историями в панели офиса пока нет.

1. Подтвердить биографию, образование и должности по официальным материалам.
2. Добавить запись с уникальным `slug`, именем, ролью, описанием, учёбой,
   биографией, этапами карьеры, датой сверки и ссылками на источники.
3. Положить фотографию в `frontend/public/assets/photos`, указать имя файла,
   исходные ширину и высоту, подпись. Источник фотографии внести в
   [список медиа](media-sources.md).
4. Проверить главную, список и полную страницу на компьютере и телефоне.
   Команда: `uv run --directory frontend pytest -q tests/python/test_alumni_stories.py`.

Порядок записей задаёт порядок карточек; на главной показываются первые три.
Отсутствующие даты не вычисляются по длительности образовательной программы.
Текст из внешнего источника пересказывается; HTML в полях не поддерживается.

Один источник поставляется в Python-пакете web и используется при генерации
зеркала. Новые страницы входят в обычную сборку, изменения API и базы не нужны.
Ранее открытая анонимная страница истории доступна для офлайн-чтения PWA
по общим правилам: до семи дней, с датой сохранённой копии. Ответы для вошедших
пользователей для офлайн-чтения не сохраняются.

## Выпуск

После слияния применяется обычный порядок
[обновления и отката](../operations/deploy-runbook.md).
На целевом сайте проверить блок `/#alumni-stories`, `/stories` и все три
полные страницы, загрузку фотографий и возврат на главную. Публичное зеркало
пересобирается из того же коммита. Откат выполняется на предыдущую ревизию
web; миграции данных отсутствуют.
