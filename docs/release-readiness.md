## Изменения релиза

- Бессрочные HMAC-ссылки Telegram заменены случайными одноразовыми кодами; в БД только хеш.
- Выход администратора и погашение reset-ссылки сохраняются в PostgreSQL.
- Ссылка подтверждения почты не активирует suspended-аккаунт.
- API стартует после CMS и миграций. Настройки поддержки, Telegram, очереди писем и резервов доходят до контейнера.
- Production-конфигурация проверяет разные секреты, HTTPS-origin, полный канал офиса и парные ключи интеграций.
- SQL-миграции и индексы применяются единым шагом; роль API создаётся автоматически.
- `/ready` проверяет схему, а не только соединение. Статусы внешних доставок не подменяются зелёными индикаторами.
- Фото профиля до 3 МБ проходят прокси; ошибка обновления профиля не удаляет старый файл.
- `.dockerignore` исключает секреты и локальные зависимости из контекста сборки; `.env.*` исключены из git.
- Исправлена запись изображений при создании товара в админке.
- Профиль содержит понятную привязку Telegram; мобильное нижнее меню сохранено.
- Архивные staged-тесты исключены из обычного Playwright-запуска и включаются отдельно.

и статическое зеркало учитываются как разные виды доказательств.

## Что требуется для публичного запуска

1. VPS, DNS и доступ оператора: запустить `scripts/deploy.sh` с внешним production env,
   проверить сертификат, HTTPS и публичный `/api/ready`. Это пока не выполнялось.
2. Рабочий SMTP и адрес офиса: проверить письмо на реальном почтовом ящике. Mailpit
   подтверждает работу приложения, но не DNS почты, репутацию отправителя и внешнюю доставку.
3. Заменить токен бота из переписки, задать его на сервере, зарегистрировать webhook и
   проверить диалог и Mini App в настоящем Telegram на iOS/Android. Сейчас проверены код,
   SDK-сценарии и транзакции; постоянный публичный обработчик не запущен.
4. Перенести утверждённый контент CMS и медиа: события, новости, мерч, аудио подкастов.
   На чистом стенде нет произвольно созданного production-контента. ДПО импортируется штатной синхронизацией.
5. Если при запуске нужны онлайн-платежи и push: задать ключи, провести платёжный тест
   магазина и проверку доставки на устройства. Без ключей остаются заявки без онлайн-оплаты.
6. Настроить внешнее хранение бэкапов и мониторинг uptime; выполнить приёмку на реальном
   сервере и физических телефонах. Эти проверки нельзя заменить скриншотом зеркала.

Архитектура текущего релиза рассчитана на один экземпляр API: cron и кэш отзыва
админ-сессий локальны процессу, с восстановлением отзыва из БД после рестарта.
Горизонтальное масштабирование требует отдельной координации; несколько API не запускать.

Нельзя утверждать, что все функции уже доступны посетителям, пока пункты публичного
запуска не завершены. Зеркало остаётся демонстрацией интерфейса без production-данных.
