# Изменения в праве

Статус на 22.09.2026: интерфейс реализован для сайта и зеркала. Подключён статический архив из 65 записей за 30.06–06.07.2026. Автоматический импорт, тематическая рубрикация и публикация проверенных разборов остаются следующим этапом.

## Назначение

Клуб предоставляет удобную обновляемую базу изменений российского законодательства как самостоятельную функцию рядом с ДПО и подкастами. Источник обработки – https://github.com/Bogolubov-creator/legis-digest. Связанный Telegram-ресурс, указанный владельцем, – https://t.me/LegisDigest; его тип и работа в production требуют проверки.

Название раздела: «Изменения в праве». Предлагаемый адрес: `/changes`. Раздел доступен из основной навигации, главной страницы и мобильного интерфейса. Платный доступ не вводится без отдельного продуктового решения.

Требования к оформлению и поведению закреплены в [DESIGN.md, раздел «Изменения в праве»](../DESIGN.md#изменения-в-праве--требования-к-новой-поверхности-2026-09-22). Разработка должна учитывать оба документа.

## Пользовательский сценарий

Посетитель открывает последние изменения, ищет по названию, номеру акта и тексту проверенного резюме, фильтрует по отрасли права, периоду опубликования и подтверждённым датам вступления в силу. Может открыть отдельную карточку по постоянной ссылке и перейти к первоисточнику или связанному выпуску в Telegram.

Карточка содержит название и реквизиты акта, орган принятия, дату опубликования, дату или условия вступления в силу, краткое описание изменения, источник и время обновления. Неизвестные даты прямо обозначаются как неустановленные. Поэтапное вступление отражается отдельными положениями; одна дата не подменяет весь акт. Законопроект, публикация СМИ и принятый акт имеют разные типы записей.

Связи с программами ДПО и подкастами добавляются редактором по теме конкретного изменения. Избранное и персональные уведомления – следующий этап после работающей базы.

### Удобный просмотр – обязательный объём первой версии

Чтение изменения происходит внутри клуба: на широком экране список и область чтения стоят рядом, на телефоне карточка занимает отдельный экран. Постоянная ссылка `/changes/:id` работает при прямом открытии. Возврат восстанавливает поиск, фильтры, страницу и позицию в списке.

Поиск выполняется по всему опубликованному каталогу. Фильтры, сортировка и страница сохраняются в URL; выдача разбита по 20 записей. Активные условия видны и сбрасываются по отдельности или вместе. Старый медленный ответ не должен заменять результаты более нового запроса. При фоновом обновлении уже загруженный текст остаётся доступным.

Карточка показывает полное название, реквизиты, проверенное содержание и отдельные даты без обрезки. Пользователь может скопировать постоянную ссылку и открыть первоисточник. Кнопка Telegram ведёт на конкретный пост только при известном адресе; общая ссылка на @LegisDigest явно отличается от неё. Основные материалы читаются без обязательного перехода в Telegram.

В первой версии предусмотрены загрузка, пустой каталог, отсутствие совпадений, ошибка с повтором, задержка обновления, неполнота источников и отсутствующая карточка. Публичная карточка официального акта может показывать только проверенные реквизиты, если резюме ещё не одобрено; черновой текст не передаётся клиенту.

## Основания проекта

README и `src/fetch_pravo.py` прочитаны через GitHub API 22.09.2026. Источник собирает выбранные виды актов из блоков president/government официального портала, дополняет их RSS и готовит обзоры. Нормализованная запись содержит source, block, kind, title, number, date, published, url. Полнота всего законодательства из этого не следует.

Локальная копия в Downloads дополнительно изучена для понимания артефактов; её соответствие текущему GitHub HEAD не подтверждено. Перед реализацией контракт экспорта необходимо сверить с закреплённым коммитом источника.

## Поток данных

1. legis-digest собирает исходные документы и сохраняет нормализованные записи.
2. Отдельный экспорт передаёт записи в сервер клуба по аутентифицированному каналу. GitHub с исходным кодом и Telegram-посты не подменяют рабочий источник структурированных данных.
3. Сервер проверяет схему, даты, допустимые адреса источников, размер пакета и уникальность записей. Импорт повторного пакета не создаёт дубликаты.
4. Исходные реквизиты отделены от AI-резюме. Юридические выводы и интерпретации проходят человеческую проверку перед публичной выдачей. Исправление резюме снимает старое одобрение.
5. Сайт получает опубликованные записи из серверной базы. Ссылка на Telegram прикрепляется после подтверждения публикации; сбой Telegram не уничтожает запись на сайте.

Минимальный контракт: версия схемы, идентификатор и время сборки, охваченный период, состояние каждого источника; для записи – устойчивый внешний идентификатор, тип источника, первичная ссылка, реквизиты, исходные даты, версия содержимого. Рубрики, проверенное резюме, условия вступления и редакционный статус хранятся отдельно от исходных полей. Время последней успешной синхронизации не подменяется временем открытия страницы.

Архив клуба хранится независимо от очистки временных артефактов legis-digest. Для обновлений сохраняется история версий. Импорт выполняется атомарно; неполный или испорченный пакет не удаляет предыдущую базу.

## Актуальность и публикация

Показывать охваченный период, последнюю успешную загрузку и состояние источников. Если сбор задержался или один источник недоступен, сохранять прежние записи и явно показывать задержку или неполноту. Не использовать формулировки «все изменения» и «полная база законодательства». Отсутствие новых записей отличается от ошибки загрузки.

Секреты импорта и Telegram доступны только серверу. В публичную выдачу не попадают черновики, внутренние замечания проверяющих, журналы, данные подписчиков и ключи. Внешние материалы отображаются как данные с безопасным экранированием.

Проверка artel-invariant-guardian: существование артефакта, отметки `.sent` или поста не подтверждает проверку юристом. Импортируемое AI-резюме получает статус `pending_review`; одобрение связывается с `reviewer_id`, `reviewed_at` и хешем текста. URL Telegram Bot API с токеном не должны попадать в журналы. Сетевые функции источника нельзя переносить без отдельной проверки маскирования секретов.

## Приёмка

На настоящем пакете проверить импорт, повтор без дублей, исправление записи и сохранение архива. Проверить отказ источника, просроченную синхронизацию и неполный пакет. Непроверенное AI-резюме не выдаётся публично. Поиск, фильтры и постоянные ссылки работают на компьютере и телефоне; первоисточник относится именно к выбранному акту. Доступность production и доставка в Telegram подтверждаются отдельно от локальных тестов.

Сценарий удобства: найти акт по номеру; ограничить период опубликования; открыть результат; прочитать содержание внутри клуба; скопировать ссылку; вернуться к прежней позиции. Повторить на телефоне и с клавиатуры. Отдельно открыть скопированную ссылку в новой вкладке и проверить восстановление материала. Визуальные критерии и размеры экранов определены в DESIGN.md.
