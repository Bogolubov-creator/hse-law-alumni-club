# Контекст проекта — «Клуб выпускников факультета права НИУ ВШЭ»

Онбординг-документ для того, кто присоединяется к проекту. Даёт картину целиком:
что это, из чего собрано, как поднять локально, где что лежит и по каким правилам
(«канону») всё сделано.

---

## 1. Что это

Веб-портал клуба выпускников факультета права НИУ ВШЭ. Три больших контура:

- **Публичный сайт** — главная, витрина ДПО (программы дополнительного образования),
  витрина мерча, новости, карточки программ.
- **Личный кабинет выпускника (ЛК)** — вход по e-mail/паролю, уровень и баллы
  (геймификация), достижения, персональная скидка, «мои заявки», профиль.
- **Админка учебного офиса** — верификация выпускников, начисление баллов/скидок,
  смена статусов заявок, обзор.

**Важный канон:** оплаты на сайте нет. Корзина оформляет **заявку**, с человеком
связывается менеджер учебного офиса. Скидка выпускника действует **только на ДПО**,
на мерч — нет.

---

## 2. Стек

Монорепозиторий на **pnpm workspaces**:

| Пакет | Что | Технологии |
|---|---|---|
| `apps/web` | Фронтенд (SPA) | Vite + React + TypeScript + Tailwind, react-router, TanStack Query, zod |
| `apps/api` | Бэкенд (BFF) | Fastify + TypeScript + zod, JWT-сессии, @directus/sdk |
| `packages/shared` | Общий код | Типы, zod-схемы ответов, чистые функции (геймификация, корзина, деньги), сиды. Есть тесты (vitest) |
| `scripts` | Скрипты | `directus-bootstrap.ts` (схема/роли/сиды), `sync-hse-dpo.ts` (каталог ДПО) |
| `infra` / `docker-compose.yml` | Инфраструктура | Docker: postgres + Directus + api + web + Caddy (reverse-proxy) |

**Directus** (headless CMS) поверх **PostgreSQL** — хранилище данных и админ-панель CMS.
`apps/api` — прослойка между фронтом и Directus (наружу Directus не светим; фронт ходит
только в `/api`). Caddy проксирует `/` → web, `/api` → api.

---

## 3. Как поднять локально

Нужен **Docker** и **pnpm**.

```bash
# 1. Установить зависимости
pnpm install

# 2. Создать .env из примера и заполнить секреты (см. .env.example)
cp .env.example .env
#   ВАЖНО: .env в гите нет (он в .gitignore). Секреты каждый заводит у себя.
#   Минимум: пароли БД/админа, AUTH_SECRET (>=32 симв.), DIRECTUS_SERVICE_TOKEN.

# 3. Поднять весь стек (соберёт образы и прогонит bootstrap-сиды)
docker compose up -d --build
```

Адреса после запуска:

| Что | URL |
|---|---|
| Сайт | http://localhost |
| Личный кабинет | http://localhost/lk |
| Админка офиса | http://localhost/#/admin |
| API health / ready | http://localhost/api/health · http://localhost/api/ready |
| Directus (CMS-админка) | http://localhost:8055 |

`bootstrap` — одноразовый сервис: создаёт коллекции/поля/роли, сервисный токен, сиды
(уровни, правила баллов, достижения, программы, товары, новости) и тестовые аккаунты.
Идемпотентен — повторный запуск ничего не ломает.

### Грабли окружения (важно)
- **Кириллица в пути ломает Docker BuildKit.** На macOS папка проекта называется
  кириллицей — используется ASCII-симлинк, а сборка идёт с `COMPOSE_BAKE=false`.
  Если поднимаешь в кириллическом пути и падает BuildKit — сделай симлинк на латинице
  и запускай docker-команды через него.
- **Directus не принимает e-mail с TLD `.local`.** Тестовые аккаунты — на `@club.example.com`.

## 4. Ключевые механики

### Геймификация (единый источник — `packages/shared/src/gamification.ts`)
- **Баллы** пишутся в `points_ledger` (источник правды) → пересчитывается кэш
  `points_cached` / уровень.
- **Уровни:** Выпускник (5%) → Друг клуба (10%) → Знаток (15%) → Амбассадор (20%).
- **Скидка** = `min(база уровня + clamp(personal, 0..10), 25)` — справочная (оплаты нет).
- **Достижения** — 10 штук, набор и оформление повторяют дизайн (Claude Design):
  ромбы teal→navy (получено) / оранжевый (следующее) / soft (закрыто), символы ✓@♥✎★.
  Прогресс считается в коде (`achievementProgress`) из статистики выпускника.
- **Decay** — −15% баллов за месяц неактивности (cron, идемпотентно по месяцу).

### Каталог ДПО — реальные программы ВШЭ
Программы берутся с сайта ВШЭ (факультет права, `orgUnit=22753`):
- актуальный набор: https://www.hse.ru/edu/dpo/?orgUnit=22753
- неактуальные: https://www.hse.ru/edu/dpo/?onlyNonactual=1&orgUnit=22753

Сейчас источник — зеркало в `packages/shared/src/seeds.ts` (`PROGRAMS_SEED`), заполненное
по актуальному набору. **«Связка» авто-актуализации** — `scripts/src/sync-hse-dpo.ts`:
upsert по slug + архивирование программ, которых больше нет в источнике. Точка, куда
подключается парсер hse.ru, — функция `fetchHseDpo()` (сейчас возвращает зеркало).

Запуск синхронизации:
```bash
DIRECTUS_URL=http://localhost:8055 pnpm --filter @club/scripts exec tsx src/sync-hse-dpo.ts
```

### Сообщество и интересы
- **«Сообщество» в ЛК** — «найти своих»: список верифицированных однокурсников того же
  выпуска (cohort) и/или той же образовательной программы (edu_program) с кнопкой
  «В друзья». Связи — коллекция `alumni_friends` (pending → accepted; встречная заявка
  автоматически принимает дружбу). API: `GET /me/classmates`, `POST /me/friends`.
- **Интересы в юриспруденции** — справочник `LEGAL_INTERESTS` (@club/shared/interests),
  выпускник выбирает до 8 чипов в Профиле (`alumni.interests_json`); ввод фильтруется
  строго по справочнику (`sanitizeInterests`). Интересы видны однокурсникам в «Сообществе».
  При появлении самостоятельной регистрации — включить выбор интересов в онбординг.

### Безопасность
rate-limit, helmet, CORS-allowlist, bodyLimit, trustProxy; собственные JWT-сессии
(`AUTH_SECRET`, 7 дней для выпускника; отдельный `ADMIN_AUTH_SECRET`, 12 ч, scope=admin);
UUID-сессии корзины; рантайм-валидация ответов фронта через zod-схемы из `@club/shared`.

## 5. Структура репозитория

```
apps/
  web/   src/pages/       # Home, Dpo, Program, Merch, Cart, News, Lk, Profile
         src/admin/       # AdminApp (админка офиса)
         src/components/  # SiteShell, Modal, Toast
         src/lib/         # api (клиент /api), cart, queries
  api/   src/routes/      # content, me, orders, cart, auth, admin, ...
         src/lib/         # directus (типизированная схема), auth, engine (геймификация), notify
packages/shared/src/      # gamification, cart, order-calc, order, responses (zod), seeds
scripts/src/              # directus-bootstrap, sync-hse-dpo
design-export/            # исходные макеты Claude Design (*.dc.html) — источник правды по UI
docs/                     # directus-schema.md и пр.
docker-compose.yml, infra/ Caddyfile
```

**Дизайн-макеты** лежат в `design-export/*.dc.html` (Главная, Дашборд ЛК, Профиль,
Витрина ДПО, Карточка программы, Витрина мерча, Корзина и заказ, Дизайн-кит, Админка) —
это источник правды по внешнему виду; реализация сверялась с ними.

**Палитра/шрифты (канон):** ohra `#EC5A13`, hse-blue `#11296B`, grafit `#14181F`,
kost `#FBF3E8`; шрифты Unbounded (заголовки) / Onest (текст) / Martian Mono (моно/цифры).
Тире — только среднее «–»/«—», не дефис.

## 6. Разработка

```bash
pnpm --filter @club/shared build      # собрать общий пакет (типы для api/web)
pnpm --filter @club/shared exec vitest run   # тесты общей логики
pnpm --filter @club/api build         # typecheck api
pnpm --filter @club/web build         # typecheck + сборка фронта
pnpm --filter @club/web dev           # дев-сервер фронта (Vite)
pnpm --filter @club/api dev           # дев-сервер api
```

Общая логика денег/корзины/геймификации вынесена в чистые функции в `@club/shared` и
покрыта тестами — правь бизнес-правила там, а не в роутах.

## 7. Текущее состояние

MVP собран и проходил многоагентное ревью (безопасность, типы, тесты, UX) и сверку с
дизайн-макетами. Реализованы витрины, ЛК с геймификацией, корзина-заявка (без оплаты),
админка офиса, mini-app-ядро (Telegram initData + рефералка).

**Открыто / требует внешних секретов:** боевые токены уведомлений
(`OFFICE_TG_BOT_TOKEN`, `SMTP_*`) и `TELEGRAM_BOT_TOKEN` для живого входа mini-app —
код готов, без токенов уходит в лог. Продовый деплой и Lighthouse/a11y-аудит на проде.

Осознанно отложено (по продуктовому решению): загрузка аватара, тёмная тема,
3-шаговый мастер оформления корзины, in-app CRUD в админке (сейчас → Directus Studio),
цветовой селектор мерча.
