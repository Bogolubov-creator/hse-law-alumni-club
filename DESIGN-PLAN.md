## 0. Дизайн-прочтение

> Читаю это как: **редизайн-эволюцию внутреннего портала закрытого клуба** для конечной
> известной аудитории в сотни человек, с **документально-реестровым** языком, опирающимся
> на существующий канон (охра + синий Вышки, Unbounded / Onest / Martian Mono).

Две поверхности с противоположными режимами:

| | A. Внешний контур | B. Личный кабинет |
|---|---|---|
| Экраны | `/`, витрины, `/join`, новости, события | `/lk`, `/lk/profile`, админка |
| Задача | объяснить и довести до заявки | быстро и без сюрпризов |
| DESIGN_VARIANCE | 7 | 3 |
| MOTION_INTENSITY | 4 (один оркестрованный момент) | 1 (только состояния) |
| VISUAL_DENSITY | 4 | 7 |

Режим редизайна: **preserve**. IA, маршруты, контракты API и копирайт-голос сохраняются.
Меняется система, а не продукт.

## 1. Токены – ядро работы, а не подготовка к ней

### 1.1 Почему это первый пункт, а не пятый

Проверено по коду: **системы токенов не существовало ни на одном шаге цепочки.**
В `design-export/Дизайн-кит.dc.html` – ноль CSS-переменных, только сырые hex в разметке.
Оттуда они дословно перенесены в код: **572 строки с захардкоженным hex, 779 строк
с `style={{…}}`** на 7152 строки `apps/web/src`. Tailwind-конфиг содержит только цвета,
три шрифта и два радиуса – ни шкалы размеров, ни spacing, ни состояний.

Значит v2 – это в первую очередь построение системы, от которой поедет всё остальное.
Визуал без этого шага – ещё один слой хардкода.

### 1.2 Архитектура: два слоя, не один

Одноуровневые токены (`--ohra: #EC5A13`) не решают задачу: компонент всё равно решает,
какой цвет чему. Нужны два слоя.

**Слой 1 – палитра.** Сырые цвета канона и дизайн-кита под осмысленными именами.
Единственное место, где вообще встречается hex.

```css
:root {
  /* Канон – неприкосновенны */
  --p-ohra:        #EC5A13;  /* акцент клуба */
  --p-blue:        #11296B;  /* синий Вышки, институциональный якорь */

  /* Законное расширение из дизайн-кита */
  --p-ohra-deep:   #C9450E;  /* охра для текста и hover */
  --p-karmin:      #B5331B;  /* ошибки, отказ верификации */
  --p-blue-bright: #2E6FAE;  /* ссылки и данные на тёмном */
  --p-steel:       #2C6E80;  /* вторичный холодный, нейтральные статусы */
  --p-brass:       #C49A45;  /* статус, уровень, награда */
  --p-brass-light: #E3C272;  /* статус на тёмном */
  --p-ink:         #14181F;  /* графит: основной текст и тёмная поверхность */
  --p-ink-soft:    #272C38;  /* вторичный текст */
  --p-paper:       #FBF3E8;  /* кость: основной фон */
  --p-paper-2:     #F2E3CF;  /* вторичная поверхность */
  --p-line:        #E5E7EB;  /* границы */
}
```

`#15375E` (`kobalt` из `tailwind.config.ts`) **удаляется** – самодеятельность,
в дизайн-ките отсутствует, канон говорит `#11296B`.

**Слой 2 – семантика.** Шесть именованных ролей, как просит бриф. Компоненты знают
только их. Здесь же разводятся светлая тема, тёмная тема ЛК и версия для слабовидящих.

```css
:root {
  --bg:            var(--p-paper);      /* фон полотна */
  --surface:       #FFFFFF;             /* поднятая поверхность */
  --text:          var(--p-ink);        /* основной текст */
  --text-muted:    var(--p-ink-soft);   /* вторичный текст */
  --border:        var(--p-line);       /* границы и разделители */
  --accent:        var(--p-ohra);       /* заливка акцента */
  --accent-text:   var(--p-ohra-deep);  /* акцент, когда это текст */
}
```

### 1.3 Контраст: где охра работает, а где нет

Бриф просит проверить охру отдельно. Проверил – считал по WCAG, не на глаз:

| Пара | Контраст | Вывод |
|---|---|---|
| охра `#EC5A13` на белом | **3.48:1** | текстом нельзя |
| охра на `kost` | **3.16:1** | текстом нельзя |
| **`kost` на охре (текущая кнопка «Вступить в клуб»)** | **3.16:1** | **провал AA** |
| `ohra-deep #C9450E` на белом | 4.84:1 | AA, годится текстом |
| `ohra-deep` на `kost` | **4.40:1** | не дотягивает |
| **`#6B7280` на `kost`** | **4.39:1** | **провал AA** |
| `#6B7280` на белом | 4.83:1 | AA |
| охра на графите | 5.12:1 | AA |
| `kost` на синем Вышки | 12.29:1 | AAA |
| `blue-br` на графите | **3.39:1** | ссылки на тёмном не дотягивают |
| латунь на графите | 6.83:1 | AA |

**Три подтверждённых дефекта, а не риска:**

1. **Главная кнопка сайта не проходит AA.** `bg-ohra text-kost` при 14–15px semibold –
   3.16:1. Это `SiteShell`, то есть кнопка на каждой странице.
2. **Правка контраста из коммита `754c8be` не достигла цели.** Там `#9aa0aa → #6B7280`
   «WCAG AA». На белом это верно (4.83), но фон полотна – `kost`, а на нём 4.39. Проверяли
   не на том фоне.
3. `ohra-deep` как цвет ссылки на кремовом (`Home.tsx:377`) – 4.40, тоже мимо.

**Правило, которое из этого следует и ложится в токены:**

> Охра – это **заливка и акцент на тёмном**, но не текст на светлом.
> На кремовом полотне текстом работает только `--p-ink` / `--p-ink-soft`.
> Текст на охряной заливке – `--p-ink` (графит на охре: 8.7:1), а не `kost`.

Это меняет вид главной кнопки: тёмный текст на охре вместо светлого. Осознанное
отступление от текущего вида ради AA. Если вам важнее прежний светлый текст –
альтернатива: заливка `--p-ohra-deep` со светлым текстом (`kost` на `#C9450E` = 4.40,
тоже не дотягивает) либо графитовая кнопка с охряной обводкой. **Рекомендую тёмный
текст на охре** – сохраняет узнаваемость акцента и проходит AAA.

### 1.4 Типографика

Роли из канона сохраняются, добавляется то, чего не было – шкала.

| Роль | Шрифт | Где | Начертания |
|---|---|---|---|
| Display | Unbounded | заголовки, крупные цифры, знак | 600 / 800 |
| Body | Onest | весь текст и UI | 400 / 500 / 600 |
| Data | Martian Mono | метки, коды, баллы, номера заявок, годы | 400 / 500 |

**Шкала** (канон 12/14/16/20/28/40/64, оформляю в токены с clamp):

```css
--t-caption: 12px;                          /* моно-метки */
--t-small:   14px;
--t-body:    16px;
--t-lead:    20px;
--t-h3:      clamp(22px, 2.2vw, 28px);
--t-h2:      clamp(28px, 4vw,   40px);
--t-h1:      clamp(34px, 7vw,   64px);
```

**Трекинг:** display −0.01em (канон), моно-метки +0.16em, остальное 0.
**Мера строки:** 65ch для абзацев – сейчас не ограничена нигде.
**Цифры:** `font-variant-numeric: tabular-nums` на Martian Mono – баллы и суммы не должны
прыгать при обновлении.

Типографика несёт характер через **контраст ролей**, а не через размер: Unbounded только
на заголовках и числах статуса, Martian Mono на всём, что является данными из реестра.
Это же и есть сигнатура – см. §3.

**Шрифты уезжают с Google Fonts на self-host** (`@font-face` + `font-display: swap`
+ `preload`). Сейчас `index.html:86` тянет три семейства с CDN: это гарантированный
layout shift (планка качества требует его отсутствия) и точка отказа в РФ.

### 1.5 Прочие токены

```css
--r-sm: 8px; --r-md: 12px; --r-lg: 18px;      /* канон 12/18, +8 для мелких элементов */
--space: 4px;                                  /* шаг сетки, всё кратно */
--container: 1180px;                           /* как сейчас в SiteShell */
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--dur-fast: 140ms; --dur-base: 200ms;
```

Радиусы фиксируются как система: интерактивное – `--r-md`, карточки – `--r-lg`,
мелкие бейджи – `--r-sm`. Сейчас в коде встречаются 8, 10, 11, 12, 14, 16, 18, 20 px
вперемешку.

## 2. Layout

### Концепция в одном предложении

> **Портал выглядит как реестр выпускников, а не как лендинг: горизонтальные записи
> с моноширинными полями-подписями вместо сетки одинаковых карточек.**

**Вариант B. «Текущая структура, поднятая по качеству»** – оставить секции-сетки
3×карточки, поменять только токены, типографику и состояния.

| | A «Реестр» | B «Поднять текущее» |
|---|---|---|
| Риск | средний, меняется композиция главной | низкий |
| Убирает три одинаковых ряда по 3 карточки | да | нет |
| Убирает `01/02/03` там, где нет последовательности | да | частично |

секции формата «три равные карточки»** (витрины, шаги, причины) плюс новости –
это ровно тот шаблон, который бриф запрещает, и он же самый узнаваемый признак
генерации. Вариант B оставит структуру, из-за которой страница и выглядит шаблонной.
Горизонтальная запись реестра одновременно решает и это, и таймлайн: **история клуба
перестаёт быть отдельной pinned-секцией с гигантской пустотой** (проверено скриншотом
`viewport-home-2200.png` – под карточками таймлайна пустует больше трети экрана)
и становится теми же записями реестра.

не создаст иерархию.

### 2.3 Адаптив – первоклассное требование, а не полировка

Вайрфреймы выше – десктоп. Правила схлопывания задаются **вместе с ними**, а не потом:

- **≥1024px** – как нарисовано.
- **768–1023px** – реестр главной сохраняет две колонки, метка уезжает над записью;
  ЛК схлопывается в одну колонку, порядок блоков сохраняется.
- **<768px** – одна колонка везде; `--container` = 100% − 2×16px; шапка ЛК
  «Удостоверение» остаётся первым экраном; навигация уходит в нижние табы
  (забираем `TabBar` из мобильной оболочки как адаптивный компонент, см.
  `docs/mobile-shell-inventory.md`).
- **360px** – нижняя граница проверки. Моно-метки не переносятся, числа
  не обрезаются, кнопки не переносятся на две строки.

## 3. Signature: «поле бланка»

Один элемент, из мира предмета, не абстрактный градиент.

**Что это:** тонкая линия с моноширинной подписью под ней – типографика официального
бланка, где под чертой мелко подписано, что в неё вписывают.

```
Сергей Кондратьев
▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
ВЫПУСК 2026 · ПУБЛИЧНОЕ ПРАВО
```

**Откуда:** удостоверение, реестр, зачётная книжка, опись. Мир документа, в котором
живёт факультет права. Константа брифа «Удостоверение Вышки» – прямое основание.

**Что кодирует:** «это данные из реестра, подтверждённые офисом», а не украшение.
Поэтому элемент **никогда не появляется там, где нет данных** – это не разделитель.

**Где работает:**

| Поверхность | Применение |
|---|---|
| Внешний контур | записи истории клуба (год под чертой), подписи витрин, цифры клуба |
| Кабинет | шапка удостоверения, метка-значение в каждом блоке, номера заявок |
| Формы | подпись под полем ввода вместо плейсхолдера-метки |
| Админка | заголовки колонок таблиц |

**Почему это, а не фасеточная Фемида:** Фемида уже есть и остаётся знаком и ассетом
героя. Но знак – это логотип, а не система: он не масштабируется на 40 экранов и
не работает в плотном кабинете. «Поле бланка» – это правило набора, которое работает
и на герое в 64px, и на строке таблицы в 12px, и одинаково уместно на обеих
поверхностях с противоположными режимами.

## 4. Движение

Решение по Q7 зафиксировано: **один оркестрованный момент**, не россыпь.

- **Внешний контур:** единственный момент – сборка героя при загрузке. Фемида
  проявляется, заголовок и метки въезжают со стагером 40–60мс, `--ease-out`,
  ≤300мс. Больше на странице не анимируется ничего, кроме состояний.
- **Кабинет:** движения нет. Только `:active` на нажатии (`scale(0.98)`, 140мс)
  и переходы состояний. Действия здесь совершаются десятки раз в день – анимация
  делает их медленнее.
- **Маркиза** остаётся одна на странице, `linear`, как сейчас.
- `prefers-reduced-motion` отключает сборку героя и маркизу целиком; состояния
  и цветовые переходы остаются.

Анимируются только `transform` и `opacity`.

## 7. Самокритика плана

Бриф требует раскритиковать себя. Три места, где я выдавал бы то же на любой похожий бриф:

**1. Первая версия сигнатуры была «фасеточная лента из 5 цветов палитры».**
Это прямо из канона (§1 оркестрации) – и это ровно «декоративный разделитель,
ничего не кодирующий», который бриф запрещает. Лента красивая и бессмысленная:
она не несёт данных и появляется там, где нужно «разделить». Переделал на «поле
бланка», которое обязано подписывать реальные данные и потому не может стать
украшением. Канон в этом пункте перекрыт брифом.

**2. Первая раскладка кабинета была «сайдбар слева + карточки справа».**
Это дефолт любого ЛК и первое, что приходит в голову. Отказался: у кабинета
четыре раздела, сайдбар съел бы 240px ширины ради четырёх ссылок, а на 360px
всё равно схлопнулся бы. Горизонтальная навигация в шапке + плотная сетка
даёт больше места данным.

**3. Хотел предложить светлую и тёмную тему для внешнего контура.**
Убрал. Тёмная тема для публичного сайта – это работа, которую никто не попросил,
и удвоение проверок контраста. Тёмная остаётся только в ЛК, где она уже есть
и где люди сидят подолгу.

Ещё одно, что стоит сказать прямо: **вариант A для главной – это осознанный риск.**
Композиция меняется сильнее, чем «поднять текущее». Оправдание – текущая главная
содержит три подряд секции одного шаблона, и без смены композиции этот признак
не убрать никаким подбором цветов.
